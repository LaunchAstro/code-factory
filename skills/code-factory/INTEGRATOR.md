# Integration and the section end

Open at each review result, merge, rebase and section end; the section-end steps sit under Batch end. The method is [Review rounds](../../docs/METHOD.md#review-rounds) and [Section-end passes](../../docs/METHOD.md#section-end-passes); this file is what you check. Each lane runs its own Sol review and fixes; the merge script merges.

## Each review result
1. **Proofs.** Sol gives each finding a failing scenario and the lane writes the test, as METHOD's [Proofs](../../docs/METHOD.md#what-review-always-covers) says; you patch nothing into a builder.
2. **Rounds.** The loop is builder, Sol, builder fixes, Sol, until Sol approves the exact head. [Review rounds](../../docs/METHOD.md#review-rounds) sets the cap and the one ladder at it, the same in hardened production and production; a fleet piece gets no third Sol round and no extra check you grant. A ceiling with unread scope is a hold, never an approval.
3. **Fix size** ([Fixes stay small](../../docs/METHOD.md#fixes-stay-small)). A builder past those limits sends a two-line simpler design; decide it and mention it at the next check-in.
4. **Fresh heads.** A new commit needs a fresh approval; re-running old proofs is not one. A rebased approval carries only as [item 6](../../docs/METHOD.md#building-on-main) says, the one carry rule: only an identical range-diff carries; anything else gets Sol's narrow check of what changed, with the proofs it touches re-run. Hardened production adds [A2](../../docs/variants/hardened-production.md#production-learnings-adopted)'s condition for a sensitive piece; production carries as [production.md](../../docs/variants/production.md) change 2 says. Never post a `Sol verdict` status by hand; until a landing tool checks the carry, a quick Sol range-diff check stands in.
5. **No stacks**. In hardened production and production each pull request stands alone on `main` ([Pull request size](../../docs/METHOD.md#pull-request-size)). Hardened production has two exceptions: a re-cut of a reviewed over-size pull request, and a critical-path chain the owner's deadline names. Each lands only by top-carry with its gate (each reviewed head is an ancestor of the top; `main..top` holds nothing unreviewed), never train-enqueued ([A1](../../docs/variants/hardened-production.md#production-learnings-adopted)). A re-cut's final tree equals the reviewed head byte for byte (`git diff <reviewed-head> <stack-tip>` prints nothing); each piece then gets a narrow Sol check that it builds, passes its own tests and moves no behaviour between pieces.

## Batch end
1. **Cleanup passes** ([Section-end passes](../../docs/METHOD.md#section-end-passes)), in this order: thermonuclear, architecture, deslop, unslop. Cut one `cleanup/<section>` branch from the merged head. Each pass is a fresh lane that wrote none of the section, on that section's code only, loading `batch-cleanup` and only its own pass file, committing to that branch. Start the next only after checking the previous lane's DONE or NO-CHANGE line; its output head is the next input. Keep these passes out of every builder's prompt.
2. **Land the cleanup.** After unslop, open one pull request from `cleanup/<section>` (an over-size one lands in pieces as [Section-end passes](../../docs/METHOD.md#section-end-passes) says) and land it through the normal gate: Sol on its exact head, the checks and the agents' click-through, then the merge script (in production, under production.md's five strict rules too).
3. **Stage end only**, once the last section's cleanup has landed, since the passes change the head: Sol reads the whole merged stage at its exact head; the builders fix; Sol approves the exact head, the one the owner tests. Then agents run the owner's test script on staging and the owner gets the test pack. Each capability's read before its switch ([item 7](../../docs/METHOD.md#building-on-main)) runs as well.

## Always
- An accepted code head grants no deployment; keep existing deployment and owner click-through authority.
- At each section end, log a `FOR-CF` line with what the build did differently from METHOD.md, and mark any path not yet run as unproven.
