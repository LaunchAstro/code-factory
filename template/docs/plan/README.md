# Plan and evidence

[Current decisions](../current-decisions.md) is the public, project-only
baseline for this foundation. It carries the current technical decisions and
supersessions. [ADRs](../adr/README.md) explain the retained trade-offs. The
[example product](../example-product/README.md) holds one project's filled-in
decisions and its draft
[first task specification](../example-product/first-task.md), which releases no
product implementation.

## Sequence

1. Complete and independently review the local foundation.
2. Complete the separately authorised publication and hosted-control proofs.
3. Rehearse the full build loop before product code.
4. Build the project's first slice under its approved tickets, then each later
   slice as its specification is approved.

A phase name carries no deadline or authority to operate a service. The
[example product's sequence](../example-product/README.md#its-sequence) shows
one project's roadmap.

## Evidence boundaries

The original research and preparation history remain in a private archive.
They contain material outside this public project's scope and are not required
reading for an implementation ticket. This foundation retains technical
explanations rather than copying the research corpus wholesale.

A **public technical evidence digest and adjudicated review verdicts** remain
an outstanding, separately named deliverable. Historical review rounds are
not represented here as current-candidate certification. The example
product's curated
[technical references](../example-product/technical-references.md) help
reproduce its reasoning; they do not replace that digest or its verdicts.

[Publication checklist](publication-checklist.md) lists the remaining gates.
[Ruleset procedure](ruleset.md) describes intended hosted enforcement. Exact
candidate manifests, local results, and independent review reports belong
beside the candidate, outside the bytes they describe. They establish only
the properties each check actually tested.
